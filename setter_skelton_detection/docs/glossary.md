# ユビキタス言語定義

## ドメイン用語の定義（バレーボール）

| 用語 | 定義 |
| --- | --- |
| セッター（setter） | トスを上げる役割の選手。本プロジェクトの検出対象 |
| トス（set） | セッターがアタッカーへボールを供給する動作・そのボール自体 |
| トスの瞬間 | ボールがセッターの手を離れる瞬間。データセット作成時のフレーム抽出基準点 |
| アタッカー／ハイター（hitter） | トスを受けてスパイクを打つ役割の選手 |
| ブロッカー | ネット際でジャンプし相手の攻撃を防ぐ役割の選手。セッターと視覚的に紛らわしいポーズ（ジャンプ＋腕を頭上に）を取ることがあり、誤検出の原因になりうる |
| リベロ（libero） | 守備専門の選手（本プロジェクトでは現状扱っていない） |
| ローテーション | コート上の選手の配置が周期的に入れ替わるルール。ポジション判定を難しくする要因の一つ |
| ラリー | サーブから得点が決まるまでの一連のプレー |

## 技術用語の定義（ML／CV）

| 用語 | 定義 |
| --- | --- |
| keypoints（キーポイント） | 骨格を構成する関節等の座標点。本プロジェクトはCOCO準拠の17点（鼻・両目・両耳・両肩・両肘・両手首・両腰・両膝・両足首） |
| bbox（bounding box） | 対象を囲む矩形領域。`[x, y, w, h]`形式 |
| visibility（`v`） | keypointごとの可視性フラグ。`0`＝写っていないため意図的に未アノテーション（ラベル漏れではない） |
| pose estimation（姿勢推定） | 画像・動画から人物の骨格（keypoints）を推定するタスク |
| ファインチューニング | 汎用の事前学習済みモデル（`yolo11n-pose`）を、セッター特化データで追加学習すること |
| アフィン変換 | 画像の位置合わせ手法。本プロジェクトではネット位置を画像間で揃えるために使用 |
| ハードネガティブ | モデルが誤りやすい「紛らわしいが正解ではない」サンプルを、あえて負例として学習データに含めること |
| precision（適合率） | モデルが「検出した」もののうち実際に正しい割合。誤検出（他選手をセッターと誤検出）を減らす指標 |
| recall（再現率） | 実際に存在する対象のうちモデルが検出できた割合。非ジャンプ姿勢の見逃しを減らす指標 |
| ZeroGPU | Hugging Face Spacesの無料GPU実行方式。関数呼び出し単位でGPUを一時的に割り当てる |
| VLM（Vision Language Model） | 画像とテキストを扱う大規模モデル。本プロジェクトではポジション判定の実現可能性検証に使用（Qwen2-VL等） |

## UI/UX用語の定義

| 用語 | 定義 |
| --- | --- |
| 画像タブ／動画タブ | デモアプリの2つの入力モード。Gradioの`gr.Tab`で実装 |
| 骨格を検出（ボタン） | 推論を実行するボタンのラベル |
| 間引き（downsample） | 長い動画を、再生時間はそのままにフレーム数だけ減らして処理する機能 |

## コード上の命名規則

命名規則そのものは`development-guidelines.md`の「命名規則」を正とする。ここでは用語とコード上の識別子の対応のみ示す。

| ドメイン用語 | コード上の識別子 |
| --- | --- |
| セッターのkeypoints一式 | `annotations[i].keypoints`（`setter_keypoints.json`） |
| トスの瞬間フレーム抽出 | `making dataset.ipynb`、`contact_frame_finder.py`の`show_contact_sheet()` |
| 1日あたりGPU利用上限 | `UNAUTHENTICATED_DAILY_QUOTA_SEC`, `TARGET_USES_PER_DAY`（`app.py`） |
| 動画の間引き | `downsample`（引数名）, `stride`（内部変数） |
| アップロードサイズ上限 | `MAX_UPLOAD_MB`（`app.py`） |
