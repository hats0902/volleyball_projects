# ユビキタス言語定義

## ドメイン用語の定義（バレーボール）

前身`setter_skelton_detection`はセッターに限定していたが、本プロジェクトは全ポジションを検出対象とするため、各ポジションを対等に扱う。

| 用語 | 定義 |
| --- | --- |
| 選手（player） | 本プロジェクトの検出対象全般。ポジションを問わずコート上でプレー中の人物を指す |
| セッター（setter） | トスを上げる役割の選手。前身プロジェクトの唯一の検出対象だったが、本プロジェクトでは他ポジションと同列に扱う |
| アタッカー／ハイター（hitter） | トスを受けてスパイクを打つ役割の選手 |
| ブロッカー | ネット際でジャンプし相手の攻撃を防ぐ役割の選手。密集・接触が起きやすく、トラッキングのID switchの原因になりうる |
| リベロ（libero） | 守備専門の選手 |
| ローテーション | コート上の選手の配置が周期的に入れ替わるルール |
| ラリー | サーブから得点が決まるまでの一連のプレー |

## 技術用語の定義（ML／CV）

| 用語 | 定義 |
| --- | --- |
| keypoints（キーポイント） | 骨格を構成する関節等の座標点。本プロジェクトはCOCO準拠の17点（鼻・両目・両耳・両肩・両肘・両手首・両腰・両膝・両足首） |
| bbox（bounding box） | 対象を囲む矩形領域。`[x, y, w, h]`形式 |
| visibility（`v`） | keypointごとの可視性フラグ。`0`＝写っていないため意図的に未アノテーション |
| pose estimation（姿勢推定） | 画像・動画から人物の骨格（keypoints）を推定するタスク |
| ファインチューニング | 汎用の事前学習済みモデル（`yolo26n-pose`）を、収集したデータで追加学習すること。本プロジェクトでは評価結果次第で実施の要否が決まる（前身は最初から実施前提だった点が異なる） |
| mAP（mean Average Precision） | 物体検出・姿勢推定の定量的な精度指標。本プロジェクトでは`mAP50-95`を主に使用し、事前学習済みモデルの評価・ファインチューニング要否判断の根拠とする |
| インスタンス（instance） | 1画像・1フレームの中で検出された選手1人分の検出結果（bbox＋keypoints）を指す。前身は1画像1インスタンスだったが、本プロジェクトでは1画像に複数インスタンスが存在する |
| トラッキング（tracking） | 動画のフレームをまたいで同一の人物を追跡し、一貫したIDを割り当てる処理。`ultralytics`の`model.track()`で実現する |
| track_id | トラッキングによって割り当てられる、動画内で（理想的には）同一選手を指し示すID。ID switch（後述）が起こりうるため完全な同一性の保証はない |
| ID switch | トラッキング中に、見た目や動きの類似・遮蔽等が原因で、異なる人物間で`track_id`が入れ替わってしまう現象 |
| トラッカー（ByteTrack, BoT-SORT, tracktrack 等） | `ultralytics`が`model.track()`向けに提供する複数のトラッカー実装。動きの予測（カルマンフィルタ）に加え、BoT-SORT等は見た目照合（ReID）も利用する。本プロジェクトでの採用トラッカーはまだ決めておらず、評価フェーズで実測して決定する（`docs/architecture.md`「技術的制約と要件」参照） |
| ReID（Re-Identification） | 見た目の特徴から同一人物かどうかを判定する技術。同一チームはユニフォームが同じため効果が限定的と見込まれる |
| ZeroGPU | Hugging Face Spacesの無料GPU実行方式。関数呼び出し単位でGPUを一時的に割り当てる |

## UI/UX用語の定義

| 用語 | 定義 |
| --- | --- |
| 画像タブ／動画タブ | デモアプリの2つの入力モード。Gradioの`gr.Tab`で実装 |
| 骨格を検出（ボタン） | 推論を実行するボタンのラベル |
| 間引き（downsample） | 長い動画を、再生時間はそのままにフレーム数だけ減らして処理する機能 |
| 座標データダウンロード | 検出結果（bbox・キーポイント・`track_id`）をCSV/JSON形式で取得できる、本プロジェクトの新機能 |

## コード上の命名規則

命名規則そのものは`development-guidelines.md`の「命名規則」を正とする。ここでは用語とコード上の識別子の対応のみ示す。

| ドメイン用語 | コード上の識別子 |
| --- | --- |
| 選手のkeypoints一式 | `annotations[i].keypoints`（`player_keypoints.json`） |
| 動画の何フレーム目か | `frame_index`（座標エクスポートのJSON/CSV、動画入力のみ） |
| トラッキングID（動画のみ） | `track_id`（座標エクスポート、`results[0].boxes.id`由来） |
| 画像内の検出順ID（画像のみ） | `instance_id`（座標エクスポート。`track_id`とは別物、フレーム間の連続性を持たない） |
| 動画の間引き | `downsample`（引数名）, `stride`（内部変数） |
| アップロードサイズ上限 | `MAX_UPLOAD_MB`（`app.py`） |
